
# 🛒  Flipkart Sales & Seller Performance Analysis (SQL) 

Analyzing 50,000+ e-commerce orders across customers, products, and sellers to uncover revenue trends, customer value, and seller performance — using only SQL.

## 📌 Overview

A SQL analytics project examining 50,000+ Flipkart-style e-commerce orders across customers, products, and sellers. It answers **15 real business questions** — revenue trends, seller quality vs. performance, and customer value — using joins, window functions, and CTEs in SQL Server.

## 📦 Dataset

| Table | Rows | Description |
|---|---|---|
| `customers` | 5,000 | Customer ID, name, contact, city, state, gender, age group |
| `products` | 10,000 | Product ID, name, category, subcategory, brand, price |
| `sellers` | 1,000 | Seller ID, name, location, rating, total products listed |
| `sales_fact` | 50,000 | One row per order: customer, product, seller, quantity, date, shipping cost, discount, payment method, total amount, delivery status, review rating |

## 🛠 Tools Used

- **Microsoft SQL Server (T-SQL)** — written and executed entirely in **SQL Server Management Studio (SSMS)**
- Query outputs verified by re-running the full script against the dataset in this repo

## 💼 Business Questions Answered

1. Total number of orders and total revenue generated
2. Which cities generate the highest number of orders
3. Total revenue generated by each product category
4. Low-rated sellers (rating < 3) that are still generating high revenue
5. Top 10 best-selling products by quantity sold
6. Top 3 selling products (by revenue) in each category
7. Running (cumulative) total of daily revenue over time
8. Year-over-year (YoY) revenue growth
9. Seller ranking by revenue
10. Monthly and yearly sales trend
11. Orders categorized into High / Medium / Low value segments
12. Average order value by customer age group
13. Customers whose total spend is above the average
14. Combined Top-5 customers by revenue and by order count
15. Best-selling product category for each month

## 📊 Key Insights

**1. Scale:** 50,000 orders generated **₹14.76 crore (₹147.6M)** in total revenue, averaging **₹2,952 per order**.

![Q1 Overview](images/q1_overview.png)

**2. Orders are evenly spread across metros — no single-city dependency.** Jaipur, Pune, and Kolkata lead, but all 8 cities in the dataset sit within a tight 6,150–6,382 order band. This means Flipkart's demand here isn't concentrated in one region — logistics and marketing spend can be distributed fairly evenly rather than over-indexed on one metro.

![Top Cities](images/q2_top_cities.png)

**3. Category revenue is balanced, with Fashion, Beauty, and Electronics leading.** The gap between the top and bottom category is under 8% (₹25.5M vs ₹23.6M) — no single category is carrying the business, which is healthy from a risk standpoint but means there's no obvious "star category" to double down on either.

![Category Revenue](images/q3_category_revenue.png)

**4. Seller quality and seller revenue are disconnected — a real risk.** Seller `SELL_241` (rating 2.1/5) generated ₹2.33 lakh in revenue, and four other sub-3-star sellers each cleared ₹2 lakh+. High-volume, low-rated sellers are a churn risk: they're driving revenue today but likely hurting customer trust and repeat-purchase rates long-term. This is a concrete flag for the seller-quality team.

![Low Rated High Revenue](images/q4_low_rated_high_revenue.png)

**5. Order values split almost evenly into High and Medium tiers, with Low-value orders barely registering.** Medium (₹1,000–4,999) and High (₹5,000+) orders together make up **~78%** of all orders and **~96%** of revenue, while Low-value orders (12,079 of them) contribute just ₹56 lakh — under 4% of revenue. Any operational cost spent processing Low-value orders should be scrutinized.

![Value Segments](images/q11_value_segments.png)

**6. Revenue is remarkably stable month over month — no strong seasonality.** Monthly revenue holds between ₹11.3M and ₹12.7M all year, with no holiday-season spike (e.g., no clear Diwali/festive bump). This is worth flagging to the business: either the dataset doesn't model seasonal demand, or Flipkart's category mix here is seasonality-resistant — both are useful to know before planning inventory or ad spend by month.

![Monthly Trend](images/q10_monthly_trend.png)

**7. Cumulative revenue grows in a straight, predictable line — confirming the lack of seasonality above.** No inflection points, no plateaus. Useful as a sanity check that the monthly-trend finding isn't a fluke.

![Running Total](images/q7_running_total.png)

**8. Top-3-per-category analysis (window functions) surfaces category champions.** `Product_9798` leads Beauty, `Product_1505` leads Books, `Product_5153` leads Electronics — each pulling roughly 15–20% more revenue than the category's #2 product. These are the SKUs category managers should protect from stockouts.

![Top 3 Per Category](images/q6_top3_per_category.png)

## 🎯 Business Recommendations

- **Audit low-rated, high-revenue sellers.** `SELL_241`, `SELL_655`, `SELL_983`, `SELL_995`, and `SELL_783` combine sub-3 ratings with top-10 revenue. Prioritize a quality review before their issues show up in return rates or customer churn.
- **Reconsider effort spent on Low-value orders.** They're ~24% of order volume but under 4% of revenue — check if fulfillment cost per order makes these profitable at all.
- **No single category or city to over-invest in.** Revenue is balanced across categories and geographies; marketing and inventory budgets can stay diversified rather than concentrated.
- **Protect category-leading SKUs from stockouts** — `Product_9798`, `Product_1505`, `Product_5153`, and the other category #1s are each generating outsized revenue relative to peers in their category.

## 📖 SQL Concepts Covered

- Joins (`INNER JOIN`) across 4 relational tables
- Aggregate functions: `SUM`, `AVG`, `COUNT`, `ROUND`
- `GROUP BY`, `ORDER BY`, `TOP N`
- Window functions: `RANK()`, `LAG()`, running totals with `SUM() OVER()`
- `CASE` statements for segmentation logic
- CTEs (`WITH`) for multi-step logic (YoY growth, best category per month)
- Subqueries and correlated comparisons (above-average spend)
- `UNION` to combine ranked result sets

## 🚀 How to Run

1. Clone the repository:
   ```
   git clone https://github.com/<your-username>/Flipkart-Sales-Analysis.git
   cd Flipkart-Sales-Analysis
   ```
2. Create a database and load the four CSVs in `/data` into matching tables (`customers`, `products`, `sellers`, `sales_fact`) — column names in each CSV header match the schema used in the SQL file.
3. Open `Flipkart_sales_Analysis.sql` in SQL Server Management Studio (SSMS) and run each numbered query in order.
4. Compare your output against the screenshots in `/images` to verify.
